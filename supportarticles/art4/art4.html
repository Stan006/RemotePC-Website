Article: Windows Security Model

Why Windows blocks drag and drop between privilege levels

This behavior is enforced by User Account Control (UAC) and Mandatory Integrity Control (MIC) to prevent privilege escalation.

Understanding Android Permissions in RemotePC

Android apps require explicit permissions to access system features and resources. RemotePC uses a set of carefully chosen permissions to enable features like remote connectivity, file transfers, notifications, and background services. Below is a detailed explanation of each permission in our manifest.

1. Internet Access

android.permission.INTERNET is essential for RemotePC to connect devices remotely. All communication between client and server — including remote desktop sessions, data synchronization, and file transfers — relies on network access.

2. Vibrate

android.permission.VIBRATE allows the app to provide haptic feedback for notifications. For example, it can signal the start or completion of a file transfer.

3. Post Notifications

android.permission.POST_NOTIFICATIONS is required for foreground services to display persistent notifications. On Android, a foreground service must show a notification; this ensures that long-running tasks like file transfers remain active even if the app is closed by the user.

4. Foreground Service Permissions

  • android.permission.FOREGROUND_SERVICE – Required for all services that run in the foreground.
  • android.permission.FOREGROUND_SERVICE_DATA_SYNC – Specifically needed by FileReceiveService, which handles ongoing file synchronization. This type ensures the service is treated with higher priority by the system.

5. Write External Storage (Legacy)

android.permission.WRITE_EXTERNAL_STORAGE is only effective on Android API 28 and below. It allows the app to write files to shared storage. On Android 10 (API 29) and higher, the app uses the scoped storage system (MediaStore or app-specific directories), so this permission is no longer required.

6. FileProvider

The FileProvider enables secure sharing of files with other apps via content URIs. It requires:

  • grantUriPermissions="true" – Grants temporary access to external apps without exposing the entire filesystem.
  • android:exported="false" – Ensures that the provider cannot be accessed by apps outside your package unless explicitly allowed.

7. Why Each Service Needs Permissions

  • ConnectionService – A bound service that never enters the foreground. It does not require foreground service permissions.
  • FileReceiveService – A foreground service performing active file synchronization. Requires both FOREGROUND_SERVICE and FOREGROUND_SERVICE_DATA_SYNC, along with notification permission (POST_NOTIFICATIONS) to stay active when the app is closed.

Summary

Each permission in RemotePC is chosen to maximize functionality while respecting Android’s security model:

  • Network access for remote connectivity (INTERNET)
  • User notifications and foreground service persistence (VIBRATE, POST_NOTIFICATIONS)
  • Reliable foreground operation for file transfers (FOREGROUND_SERVICE, FOREGROUND_SERVICE_DATA_SYNC)
  • Legacy storage access where applicable (WRITE_EXTERNAL_STORAGE)
  • Secure file sharing (FileProvider)

This combination ensures that RemotePC provides reliable, secure, and uninterrupted functionality while adhering to Android’s modern security and background execution policies.

Key Takeaway

Drag and drop is blocked not because of a bug, but because Windows treats it as a cross-process data injection mechanism — which is restricted across integrity boundaries.
